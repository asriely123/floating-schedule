# 悬浮课表 — 技术方案

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Electron（安装时取最新稳定版，实际版本号记入开发日志） | 支持无边框、透明窗口、托盘与 Windows 原生调用，网页技术写界面最快 |
| 渲染层 | 原生 HTML / CSS / JS，无框架、无打包器 | 单页小工具，保持零构建复杂度 |
| 打包 | electron-builder，target = `portable`（win x64） | 产出绿色单 exe |
| 运行时依赖 | koffi（唯一，纯系统调用所需：user32.dll SetWindowPos 置底。预编译原生模块，无需构建工具链；electron-builder 自动打包进 asar） | — |
| 开发依赖 | electron、electron-builder | — |

## 3. 窗口实现

- `BrowserWindow`：`frame:false`、`transparent:true`（**真半透明方案**）、`alwaysOnTop:false`（**桌面挂件模式**）、`resizable:true`、`minWidth/minHeight`、`skipTaskbar:true`、`show:false` + `ready-to-show` 后再显示（避免白屏闪烁）
- 置底实现（F3）：Electron 无置底 API，用 koffi 调 `SetWindowPos(HWND_BOTTOM=1, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)`；时机 = 窗口 `show` 后 150ms + `blur` 时（点击可临时前置编辑，失焦自动回落）；koffi 加载失败时仅告警不崩溃
- 「恢复默认位置」（F12）：托盘右键菜单项，`win.setBounds(defaultBounds())` 并写回 schedule.json——窗口被拖丢时的救援入口（启动时越界校验仍兜底）
- 运行时显示器变化：监听 `display-added`、`display-removed`、`display-metrics-changed`；若窗口边界不再落在任何显示器工作区内（即几何位置已不可见），恢复到主屏工作区右下角（偏移 24px）并持久化新的边界。边界仍与任一工作区相交时不擅自移动用户正在使用的窗口；这里的“可见”指屏幕几何位置，不是 `BrowserWindow.isVisible()` 的显示/隐藏状态。
- 半透明实现注记：原用 `backgroundMaterial:'acrylic'`（Win11 系统磨砂），但实测 Electron 44.1.1 + 本机（Win11 26200，DPI 1.5）**未生效**——真实屏幕采样确认窗口完全不透明（诊断过程见开发日志）。现改为透明窗口 + CSS 自绘卡片（圆角 12px + 阴影），半透明可靠生效；若日后系统材质恢复可用再切换（两方案互斥，`transparent:true` 会禁用 backgroundMaterial）
- 圆角/阴影：透明窗口没有系统圆角与阴影，由 CSS 提供：卡片 `margin:8px` 内缩一圈 + `border-radius:12px` + `box-shadow`
- 分辨率注意：本机 scaleFactor=1.5，`screen.getPrimaryDisplay().scaleFactor` 参与真实屏幕采样坐标换算（见 SCHEDULE_SHOT 自检）
- 拖动/缩放：顶栏主体为 `-webkit-app-region: drag`；**所有可交互元素（格子、按钮）必须 `no-drag`**，否则无法点击（已知坑）
- 位置记忆：`window` 字段（x/y/width/height）存 schedule.json，**字段所有权归主进程**。窗口移动/缩放后由主进程读取 `win.getBounds()` 写入；渲染层保存设置或课表时不得提交、覆盖 `window`。启动时存在则恢复并校验仍在屏幕内（不在则回右下角）；不存在则放 `workArea` 右下角、偏移 24px

## 4. 进程与安全

- `contextIsolation:true`、`nodeIntegration:false`；渲染层一律通过 `preload.js` 中 `contextBridge` 暴露的最小 API 通信
- 页面安全：入口文档设置严格 CSP（脚本、样式、图片等仅允许入口所需的本地来源）；通过 `webContents.setWindowOpenHandler` 阻断新窗口，并阻断 `will-navigate` 等非入口导航。IPC 处理器同时校验 `event.sender` 属于本应用窗口且 `event.senderFrame.url` 等于本地入口 URL，校验失败立即拒绝。
- 暴露 API：`load()`、`save(data)`、`quit()`、`setAutoStart(bool)`、`getAutoStart()`、`version`。「复制上一周」使用应用窗口内的模态确认层，不再打开会触发 `blur → HWND_BOTTOM` 的浏览器原生确认框；真实鼠标点击负责激活窗口，渲染层只聚焦当前文本框，不保留额外的主进程补焦 IPC。`setAutoStart` 只接受布尔值并返回本次写入前后的 `{ previous, current }`，设置数据后续保存失败时按 `previous` 补偿回滚系统状态。任何非布尔自启参数都不得写入系统设置。
- 数据读写放在主进程（`fs`），渲染层只经 IPC

### 4.1 阶段 3 测试门禁契约

- 正式回归命令为 `npm test`。命令必须自动创建系统临时目录作为隔离数据目录，测试结束清理该目录；不得读写项目根目录、便携版目录或用户现有 `schedule.json`。测试超时和任一断言失败都必须以非零退出码结束。
- 所有 `SCHEDULE_*` 测试钩子（包括截图、E2E、存储、自启及其派生钩子）只有在 `SCHEDULE_TEST_MODE=1` 时才允许启用；未设置该开关时按普通运行处理，不暴露测试捷径。
- 测试模式的开机自启使用内存实现，不登记或修改 Windows 登录项；真实开机自启探测必须使用单独、显式保护的流程，开始前记录状态，结束时（包括失败和超时）恢复原状态，无法精确恢复时跳过写入式探测。
- 一次性保存失败注入必须覆盖课程格子编辑、翻周、「复制上一周」和设置保存四条路径，验证失败时不先提交 `data`、查看周、网格或设置草稿，并在对应位置显示中文错误；恢复写入后可重试成功。

## 5. 数据格式（schedule.json）

```json
{
  "version": 1,
  "settings": {
    "semesterStart": "2026-09-07",
    "weekCount": 20,
    "periodsPerDay": 8,
    "periodTimes": [
      { "start": "08:00", "end": "08:45" },
      { "start": "08:55", "end": "09:40" },
      { "start": "09:50", "end": "10:35" },
      { "start": "10:45", "end": "11:30" },
      { "start": "11:40", "end": "12:25" },
      { "start": "14:00", "end": "14:45" },
      { "start": "14:55", "end": "15:40" },
      { "start": "15:50", "end": "16:35" }
    ],
    "opacity": 0.65,
    "showWeekend": false,
    "autoStart": false
  },
  "window": { "x": 1200, "y": 700, "width": 640, "height": 480 },
  "viewWeek": 2,
  "weeks": {
    "3": { "0": ["高等数学", "", "", "体育", "", "", "", ""], "1": ["", "", "", "", "", "", "", ""] }
  }
}
```

- `settings.showWeekend`：布尔值，默认 `false`。旧数据缺失或类型非法时归一化为 `false`；该字段只控制渲染层显示 5 天还是 7 天，不决定数据是否保留。
- `weeks`：键 = 周序号（字符串，"1".."weekCount"）；值 = 天序号（"0"=周一 .. "6"=周日）→ 长度 `periodsPerDay` 的字符串数组（元素为课程名，空串=无课）。主进程始终保留并归一化 0..6；关闭周末显示不得删除 5/6 两天，复制上一周时也复制完整七天数据。
- 兼容策略：本次扩展继续使用 `version: 1`；旧 `schedule.json` 没有 `showWeekend` 或 5/6 两天时仍可直接读取，界面默认保持五列，缺失的周末数据在首次写入对应课程时创建。
- `viewWeek`：最近查看的周，启动时恢复；缺失或越界（超出 1..weekCount）时回退当前周
- 当前周计算：`week = floor((本周周一 - semesterStart) / 7) + 1`，夹在 `[1, weekCount]`；`semesterStart` 为空时回退为第 1 周
- 保存策略：编辑确认后即保存；先在数据目录写临时文件并完成校验，再以原子方式替换主文件。仅当现有主文件可读取且结构有效时，才将它轮换为 `schedule.bak`；主文件损坏时**不得用损坏内容覆盖有效 bak**。保存失败必须经 IPC 返回错误，不得静默吞掉。
- 缺省/损坏容错：主进程对全部字段做类型、范围与结构归一化；主文件不可读或损坏时优先从 `schedule.bak` 恢复，恢复过程不得改写有效 bak，否则返回默认值，不崩溃。
- 数据目录与权威文件：development 模式用 `app.getAppPath()`（工程根目录）；打包后 electron-builder `portable` 目标使用 `process.env.PORTABLE_EXECUTABLE_DIR` 作为数据目录，目录可写时便携版外层 exe 旁现有的 `schedule.json` 是权威数据，`schedule.bak` 与临时文件也在同目录。该目录不可写时明确回退到 Electron `userData` 目录并记录警告；一次运行只使用一个已解析的数据目录，不在两处文件之间静默择优。

## 6. 托盘图标与开机自启

- 托盘：`Tray` + `assets/tray.png`（由 `scripts/make-icon.js` 生成，纯 Node 无依赖：淡蓝圆角方块 + 白色课表行；同目录另有 256px `icon.png` / `icon.ico` 备打包用）。左键点击切换窗口显示/隐藏；右键菜单「显示 / 隐藏课表」「恢复默认位置」「退出」
- 开机自启：便携版必须使用 `process.env.PORTABLE_EXECUTABLE_FILE` 作为 `app.setLoginItemSettings({ openAtLogin: bool, path })` 的 `path`，它指向便携版外层真实 exe；`PORTABLE_EXECUTABLE_DIR` 仅用于数据目录。每次启用或关闭都要写入该外层 exe 路径，替换历史上指向 portable 临时解压目录的旧自启项。非 portable 形态使用当前实际 exe 路径；dev 模式只做 API 兼容检查，自启功能在打包版验收。
- 开机自启自检：测试前记录原有 `openAtLogin` 状态，测试完成（包括失败）后恢复该状态；存在无法精确恢复的历史项或被 Windows 禁用的项时跳过写入式探测，自检不得改变用户原有登录项。

## 7. 打包

- 命令：`npm run dist`（electron-builder `--win portable --x64`，asar 默认开启）
- `productName` 用中文「悬浮课表」，`executableName` 用 `FloatingSchedule`（避免中文 exe 名带来的兼容问题）
- 图标：第一阶段先用 Electron 默认图标；阶段 5 若时间允许做一个淡蓝色简单 .ico（可选）

## 8. 已知风险

1. `backgroundMaterial` 与 `transparent:true` 互斥——当前采用透明窗口 + CSS 自绘卡片，不启用 Acrylic。
2. 便携版放置目录可能不可写——自动回退写入 `userData`，控制台记录实际数据目录；一次运行只读写一个已解析的数据目录。
3. 数据文件被手工编辑或写入中断——读取时归一化；主文件不可读时优先恢复 `.bak`，损坏主文件不能覆盖有效 `.bak`。
4. 无任务栏入口——通过托盘左键切换显示/隐藏，右键菜单提供显示、隐藏、恢复默认位置与退出。
